## 📖 **Overview**

`libft/` is the shared support library used across the FDF codebase. It gathers
the low-level routines the engine relies on every frame and during startup:
memory utilities, string handling, linked lists, base conversion helpers,
`get_next_line`, and a custom `ft_printf` implementation.

Instead of scattering tiny helpers across runtime modules, FDF keeps them in one
static archive so the main application can depend on a stable, reusable base.

---

## ✨ **What It Provides**

| Category | Purpose |
| :--- | :--- |
| **Character Utilities** | Classification and case conversion helpers like `ft_isdigit` and `ft_toupper` |
| **String Functions** | Copying, joining, splitting, trimming, searching, and length operations |
| **Memory Functions** | Allocation, zeroing, copying, moving, comparing, and search helpers |
| **Numeric Utilities** | `atoi`, `itoa`, base conversion, and number-length helpers |
| **File Descriptor Output** | Lightweight functions for writing chars, strings, lines, and numbers |
| **Linked Lists** | Standard `t_list` creation, traversal, mutation, and mapping helpers |
| **Line Reading** | `get_next_line` for incremental file parsing |
| **Formatted Output** | `ft_printf` with flag parsing and numeric/string handlers |

## 🗂️ **Directory Structure**

| Directory | Responsibility |
| :--- | :--- |
| `includes/` | Public header with all exported declarations and shared structs |
| `srcs/char/` | Character classification and case helpers |
| `srcs/fd/` | File-descriptor output and `get_next_line` |
| `srcs/int/` | Integer parsing and small numeric helpers |
| `srcs/base/` | Base conversion and digit-count helpers |
| `srcs/lst/` | Linked-list primitives |
| `srcs/mem/` | Memory allocation and buffer operations |
| `srcs/str/` | Core string manipulation functions |
| `srcs/printf/` | `ft_printf`, flag parsing, and output formatting logic |
| `objs/` | Compiled object files generated by the local Makefile |

---

## ⚙️ **Build Flow**

The local Makefile compiles each module directory into object files under `objs/`
and archives them into `libft.a`.

### **Pipeline**

1. Source files are grouped by feature family (`char`, `mem`, `str`, `printf`, and so on).
2. Each `.c` file is compiled with `-Wall -Wextra -Werror`.
3. Output objects are mirrored into the `objs/` tree.
4. `ar rcs` packages everything into the final static library: `libft.a`.

This keeps the library fully reusable and easy to rebuild independently from the
main FDF executable.

---

## 🧠 **How FDF Uses It**

Across the project, `libft` is the common toolkit for:

- dynamic allocation with `ft_calloc`
- string parsing and path handling with `ft_strlen`, `ft_strdup`, `ft_strlcpy`, and friends
- file parsing through `get_next_line`
- debug or user-facing output through `ft_printf`
- container handling through the linked-list utilities

In practice, nearly every higher-level module in `srcs/` depends on `libft` either directly or transitively.

---

## 🔍 **Important Public Types**

### **`t_list`**
The generic singly linked-list node used by the list helpers.

### **`t_flags`**
The formatting state used internally by `ft_printf` to handle width, precision,
signs, padding, and conversion type.

---

## 🛠️ **Developer Notes**

- `libft.h` is the single public entry point for the library.
- The library is intentionally split by feature domain to keep individual folders easy to browse.
- `get_next_line` and `ft_printf` are integrated directly into the same archive so runtime modules do not need separate utility libraries.
- Because `libft.a` is a static archive, application builds stay simple and predictable.
