# 🔬 Syntax Pass Subpackage (`srcs/parsing/tokenizer/syntax`)

![Domain](https://img.shields.io/badge/Domain-Sequential_Logic_Validation-1f6feb?style=for-the-badge)
![Strictness](https://img.shields.io/badge/Strictness-Maximum-critical?style=for-the-badge)

---

## 🎯 Specific Domain
Responsible exclusively for validating the *positional sequence* of a fully lexed token stream. It guarantees that the linear arrangement of pipes, logic operators, parentheses, and redirections strictly adheres to Bash grammar rules before allowing the AST compiler to touch them.

---

## ⚙️ Core Mechanic & Algorithms
**The Linear Syntax Validator (`check_syntax`):**
1. Evaluate `check_initial_token()`. Certain tokens (`|`, `&&`, `||`, `;`) unconditionally crash the shell if they are the very first token.
2. Iterate every node in the `t_nodes` sequence passing them individually into `process_node()`.
3. `process_rules()` dispatches checks based on type:
   - **`check_pipe_sequence`:** Ensures no `|` or `&&` immediately follows another `|`.
   - **`check_redirection_sequence`:** Ensures every `<` or `>` is immediately followed by a `TOKEN_WORD` or `TOKEN_PREFIX`.
   - **Depth Tracking:** Every `(` increments `*depth`. Every `)` decrements it. 
4. At the end of iteration, if `*depth != 0`, the validator explicitly traps an "Unbalanced Parentheses" syntax panic.

---

## 📜 POSIX & Shell Compliance
> [!IMPORTANT]
> **Expansion Phantom Redirections:** A redirection operator *must* have a target. However, if the token was dynamically generated by the `env/expand` layer (e.g., inside an unquoted subshell sequence or a later variable trap), the validator actively inspects `expanded` flags to suppress false-positive syntax panics for dynamically injected targets.

---

## 🚨 Error & Signal Propagation
| Condition | Immediate Action | Upstream Impact |
| :--- | :--- | :--- |
| **Invalid Follower Node Found** | Fires `print_syntax_error(token->value)`. Returns `2`. | Halts parser. The upstream wrapper forces `state->exit_code = 2`, pre-consumes pending heredocs (critical block), and resets prompt. |
| **`depth` < 0** (e.g., `cmd )`) | Fires Unbalanced `)` syntax error. Returns `2`. | Pipeline aborted. |

---

## ⚠️ Edge Cases & Gotchas
> [!CAUTION]
> **No Memory Freeing:** The Syntax Validation module is purely read-only. It NEVER allocates and NEVER frees the token nodes. A return value of `2` indicates a failure, but memory clearance is strictly the responsibility of the upstream caller in `input/process.c`.

---

## 🔌 API Signatures
```c
/**
 * @brief Validates positional logic sequence of a linked list of tokens.
 * @param tokens The raw sequence pulled from `tokenizer()`.
 * @return `0` on pristine syntax, `2` on any Bash grammar violation.
 */
int	check_syntax(t_nodes *tokens);
```
